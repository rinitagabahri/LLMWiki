# The Swiss Cheese Model

**Big failures aren't one person's single slip — they happen when the holes in several layers of defence line up and a hazard slips all the way through.** *(James Reason, 1990.)*

## The Cheese

Each defence is a slice of Swiss cheese; its weaknesses are the holes. Usually a later slice blocks the hazard — an accident only happens when the holes in *every* layer momentarily align.

```
  hazard
    │
    ▼
  ┌────────┐  ┌────────┐  ┌────────┐  ┌────────┐
  │ ○      │  │     ○  │  │ ○      │  │    ○   │
  │    ○ ──┼──┼── ○  ──┼──┼──── ○ ─┼──┼─ ○ ────┼──▶ ACCIDENT
  │ ○      │  │  ○     │  │     ○  │  │ ○      │
  └────────┘  └────────┘  └────────┘  └────────┘
    people      technical    organis.    outside
    involved    provisions   elements    influences
```

## Three Types of Error (what slips through)

| Type | What happens |
|---|---|
| **Slip-ups** | Right plan, wrong execution — you know what to do but your hand/attention slips |
| **Blackouts** (lapses) | Memory failure — you forget a step |
| **Real mistakes** | The plan itself was wrong — you did exactly what you intended, but it was the wrong thing |

## Three Levels Where Errors Occur

- **Skill-based** — routine, automatic actions (most slips and blackouts happen here)
- **Rule-based** — applying a known rule; error = wrong rule, or right rule misapplied
- **Knowledge-based** — a novel situation with no rule to follow; reasoning from scratch, and the most error-prone

## When to Use It

- Investigating why something went wrong — look at *every* layer, not just the last person
- Designing safeguards — build redundant layers so no single hole is fatal
- When you're tempted to blame one person — check which systemic holes let it through
- Understanding others' mistakes with less blame and more accuracy

## Key Insight

Serious failures are almost never a single "human error" — they're many small weaknesses across **people, technology, the organisation, and outside circumstances** lining up at one moment. Blaming the person at the sharp end feels satisfying but fixes nothing: the holes were already there. Prevention means **adding layers and shrinking holes**, not punishing whoever happened to be standing at the last slice when the holes aligned. It's also a compassion tool — most mistakes are a system failing a person, not a person failing.

## Example

*A patient gets the wrong medicine. It's easy to blame Nurse Anya — but every layer had a hole that day:*

- *the doctor's handwriting was unclear (**people**)*
- *two drug boxes looked almost identical (**technical**)*
- *the ward was short-staffed, so no one double-checked (**organisational**)*
- *it was the end of a long night shift (**outside influence**)*

*Any one layer alone would have stopped the error. It only happened because all four holes lined up at once. So the fix isn't "punish Anya" — it's to close a hole in each layer: type the prescriptions, redesign the boxes, require a second check, fix the shift lengths.*

## Related Models

- [[consequences-model]] — both separate the *decision* from the *outcome*: a bad result can come from aligned holes, not a bad choice
- [[feedback-model]] — reframes a mistake as systemic feedback to act on, rather than personal failure to reject or resent
- [[flow-model]] — the knowledge-based level (novel, high-challenge) is the anxiety zone where errors spike
- [[double-loop-learning]] — after a failure, single-loop fixes the sharp-end slip; double-loop asks which governing assumptions left the holes aligned
- [[monte-carlo-simulation]] — failure is the improbable *alignment* of independent holes; Monte Carlo is how you'd actually estimate the odds of such compound events → see [[deciding-under-uncertainty]]
- [[black-swan-model]] — the rare, hindsight-obvious alignment of all the holes at once is a black-swan event: high-impact, unpredictable beforehand, narrated as inevitable afterward
- [[black-box-model]] — modern defence layers are increasingly black boxes you can't inspect, so the alignment of holes stays invisible until the accident report is written
- [[result-optimisation-model]] — this model diagnoses *why* the holes align but offers no proactive way to shrink them ahead of the accident; running gather→consolidate→implement three times is one such method — each round can surface and plug holes before they line up at the deadline
